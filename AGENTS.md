# AGENTS.md

## Overview

Cal.com-like booking calendar (Hexlet student project). pnpm monorepo, Russian-language docs/spec.

- `apps/backend` — NestJS 12 (ESM), Vitest, oxlint
- `apps/frontend` — React 19 + Vite + Tailwind CSS 4 + shadcn, Vitest + Testing Library
- `typespec` — TypeSpec API spec, compiles to `tsp-output/.../openapi.yaml`
- `packages/api-client` — typed SDK generated by `@hey-api/openapi-ts` into `src/client/`

**Never hand-edit `packages/api-client/src/client/`** — it's regenerated from the TypeSpec spec.

## Toolchain

All tools (Node 22, pnpm 10, hk, pitchfork) are pinned in `mise.toml`. Install via `mise install`, then `mise run setup` (installs deps + generates SDK). Run tasks through `mise run <task>` rather than calling pnpm scripts directly when a task exists.

## Key commands

- `mise run dev:backend` / `mise run dev:frontend` — dev servers (ports 3000 / 5173)
- `mise daemons start` — both dev servers as background daemons (pitchfork); also `ls` / `logs` / `stop`
- `mise run check` — the full gate: lint + typecheck + test + SDK freshness. **This is what CI runs; make it pass before finishing any change.**
- `pnpm generate:api` — recompile TypeSpec and regenerate the SDK. Required after touching `typespec/`; `mise run check` fails with a diff if the generated client is stale.

## Testing

- Backend: `pnpm --filter backend test` (vitest run). Single file: `pnpm --filter backend exec vitest run <file>`. E2E: `pnpm --filter backend test:e2e` (separate config `vitest.config.e2e.ts`).
- Frontend: `pnpm --filter frontend test`; single file the same way with `exec vitest run <file>`.
- Root `pnpm test:backend` / `pnpm test:frontend` run suites sequentially; `mise run test` = backend then frontend.

## Git conventions

Git hooks are managed by [hk](https://hk.jdx.dev/) (`hk.pkl`):

- `pre-commit` — lint
- `pre-push` — full `mise run check`
- `commit-msg` — **Conventional Commits enforced**: messages must match `type(optional-scope): description`, e.g. `feat: add booking endpoint`, `fix(slots): exclude occupied intervals`. Valid types: `feat`, `fix`, `docs`, `style`, `refactor`, `perf`, `test`, `build`, `ci`, `chore`, `revert`. Non-conforming messages are rejected.

Do not bypass hooks (`--no-verify`) — CI re-runs the same checks.

## CI

- `.github/workflows/check.yml` — `mise run setup` + `mise run check` on every push/PR.
- `.github/workflows/hexlet-check.yml` — auto-generated by Hexlet; **do not edit or delete**.

## Gotchas

- Linter is **oxlint**, not ESLint (backend uses `--type-aware` via `oxlint-tsgolint`).
- Frontend `typecheck` is `tsc -b` (project references), not plain `tsc --noEmit`.
- Business rules worth knowing before changing booking logic: slots are sliced from a fixed working-hours window; any time overlap with **any** booking (of any meeting type) makes a slot unavailable globally; no auth/timezones/cancellation by design (see README).
